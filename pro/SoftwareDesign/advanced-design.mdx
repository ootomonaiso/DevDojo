# システム設計の複雑性との戦い

## 複雑性の種類

### **本質的複雑性（Essential Complexity）**
- ビジネス要件自体の複雑さ
- ドメインロジックの複雑さ
- 削減不可能な複雑性

### **偶発的複雑性（Accidental Complexity）**
- 技術選択による複雑さ
- 設計の不備による複雑さ
- **我々が制御可能な複雑性**

### 設計の目標
**偶発的複雑性を最小化し、本質的複雑性を適切に管理する**

# ドメイン駆動設計（DDD）の深層

# DDD戦術的設計（Tactical Design）

## 核となるパターン

### **Entity vs Value Object**
```typescript
// Entity: アイデンティティを持つ
class User {
  constructor(
    private readonly id: UserId,
    private name: UserName,
    private email: Email
  ) {}
  
  // アイデンティティによる等価性
  equals(other: User): boolean {
    return this.id.equals(other.id);
  }
}

// Value Object: 値による等価性
class Money {
  constructor(
    private readonly amount: number,
    private readonly currency: Currency
  ) {}
  
  // 構造的等価性
  equals(other: Money): boolean {
    return this.amount === other.amount && 
           this.currency === other.currency;
  }
}
```

# Aggregate Pattern

## データ整合性の境界

### **Aggregate Root**
```typescript
class Order {  // Aggregate Root
  private items: OrderItem[] = [];
  private readonly customerId: CustomerId;
  private status: OrderStatus;

  addItem(product: Product, quantity: number): void {
    // ビジネスルールの強制
    if (this.status !== OrderStatus.DRAFT) {
      throw new Error("確定済み注文には商品を追加できません");
    }
    
    // 不変条件の維持
    const item = new OrderItem(product, quantity);
    this.items.push(item);
    this.recalculateTotal();
  }

  // Aggregateの境界内でのみ直接アクセス
  private recalculateTotal(): void {
    // 合計金額の再計算
  }
}
```

### **ルール**
- Aggregate外からは**Root**のみアクセス可能
- Aggregate間の参照は**ID**のみ
- 1つのトランザクション = 1つのAggregate

# CQRS（Command Query Responsibility Segregation）

## 読み取りと書き込みの分離

### **Command Side（書き込み）**
```typescript
// Domain Model: Rich Object
class BankAccount {
  private balance: Money;
  private readonly accountId: AccountId;

  withdraw(amount: Money): void {
    if (this.balance.isLessThan(amount)) {
      throw new InsufficientFundsError();
    }
    this.balance = this.balance.subtract(amount);
    // Domain Event発行
    this.addEvent(new MoneyWithdrawnEvent(this.accountId, amount));
  }
}

// Command Handler
class WithdrawMoneyHandler {
  handle(command: WithdrawMoneyCommand): void {
    const account = this.repository.findById(command.accountId);
    account.withdraw(command.amount);
    this.repository.save(account);
  }
}
```

# Event Sourcing

## 状態ではなくイベントを保存

### **従来のアプローチ**
```sql
-- 現在の状態のみ保存
UPDATE accounts SET balance = 1000 WHERE id = 'acc-123';
```

### **Event Sourcing**
```typescript
// イベントストリーム
const events = [
  new AccountOpenedEvent('acc-123', 1500),
  new MoneyWithdrawnEvent('acc-123', 300),
  new MoneyDepositedEvent('acc-123', 200),
  new MoneyWithdrawnEvent('acc-123', 400)
];

// 状態の復元
class BankAccount {
  static fromEvents(events: DomainEvent[]): BankAccount {
    const account = new BankAccount();
    events.forEach(event => account.apply(event));
    return account;
  }

  private apply(event: DomainEvent): void {
    switch(event.constructor) {
      case AccountOpenedEvent:
        this.balance = new Money(event.initialBalance);
        break;
      case MoneyWithdrawnEvent:
        this.balance = this.balance.subtract(event.amount);
        break;
      // ...
    }
  }
}
```

---

# Event Sourcingの深い利点

## **完全な監査証跡**
- すべての変更が記録される
- 「なぜこの状態になったか」が追跡可能
- 規制要件への対応（金融、医療等）

## **時間軸での分析**
```typescript
// 過去任意の時点での状態復元
const accountAt2023Jan = BankAccount.fromEventsUntil(
  events, 
  new Date('2023-01-01')
);

// ビジネス分析
const monthlyWithdrawals = events
  .filter(e => e instanceof MoneyWithdrawnEvent)
  .filter(e => e.timestamp.getMonth() === targetMonth)
  .reduce((sum, e) => sum + e.amount, 0);
```

## **イミュータブルデータ**
- 過去のイベントは変更不可
- 並行性問題の軽減
- 分散システムでの一貫性

# マイクロサービスアーキテクチャ

## サービス分割の原則

### **単一責任原則（SRP）at Service Level**
```
❌ 悪い分割
├── UserService
│   ├── ユーザー管理
│   ├── 認証・認可
│   ├── 通知送信

├── NotificationService     (通知)
└── ReportingService       (レポート)
```

### **データベース分離**
- サービス間でのDB共有は禁止
- データアクセスはAPIのみ
- **Database per Service**パターン

# サービス間通信の設計

## **同期 vs 非同期**

### **同期通信（REST API）**
```typescript
// 直接API呼び出し
class OrderService {
  async createOrder(orderData: CreateOrderRequest): Promise<Order> {
    // 在庫確認（同期）
    const inventory = await this.inventoryClient.checkStock(orderData.items);
    if (!inventory.isAvailable) {
      throw new OutOfStockError();
    }

    // 支払い処理（同期）
    const payment = await this.paymentClient.processPayment(orderData.payment);
    
    return this.createOrderInDatabase(orderData, payment.id);
  }
}
```

**問題**: サービス障害の連鎖、レスポンス時間の劣化

### **非同期通信（Event-Driven）**
```typescript
class OrderService {
  async createOrder(orderData: CreateOrderRequest): Promise<OrderId> {
    const orderId = OrderId.generate();
    
    // イベント発行
    await this.eventBus.publish(new OrderCreationRequestedEvent(orderId, orderData));
    
    return orderId; // 即座に応答
  }
}

// 他サービスでの処理
class InventoryService {
  @EventHandler(OrderCreationRequestedEvent)
  async handleOrderCreationRequested(event: OrderCreationRequestedEvent): Promise<void> {
    const isAvailable = await this.checkStock(event.items);
    
    if (isAvailable) {
      await this.eventBus.publish(new StockReservedEvent(event.orderId));
    } else {
      await this.eventBus.publish(new StockUnavailableEvent(event.orderId));
    }
  }
}
```

# Saga Pattern

## 分散トランザクションの管理

### **Choreography Saga**
```typescript
// サービス間の協調によるワークフロー
class OrderService {
  @EventHandler(StockReservedEvent)
  async handleStockReserved(event: StockReservedEvent): Promise<void> {
    // 次のステップをトリガー
    await this.eventBus.publish(new ProcessPaymentRequestedEvent(event.orderId));
  }

  @EventHandler(PaymentProcessedEvent)
  async handlePaymentProcessed(event: PaymentProcessedEvent): Promise<void> {
    await this.finalizeOrder(event.orderId);
    await this.eventBus.publish(new OrderConfirmedEvent(event.orderId));
  }

  @EventHandler(PaymentFailedEvent)
  async handlePaymentFailed(event: PaymentFailedEvent): Promise<void> {
    // 補償アクション
    await this.eventBus.publish(new ReleaseStockRequestedEvent(event.orderId));
    await this.cancelOrder(event.orderId);
  }
}
```

### **Orchestrator Saga**
```typescript
class OrderSagaOrchestrator {
  async processOrder(orderId: OrderId): Promise<void> {
    try {
      await this.reserveStock(orderId);
      await this.processPayment(orderId);
      await this.finalizeOrder(orderId);
    } catch (error) {
      await this.compensate(orderId, error.step);
    }
  }

  private async compensate(orderId: OrderId, failedStep: SagaStep): Promise<void> {
    // 実行済みステップの逆順で補償
    const executedSteps = this.getExecutedSteps(failedStep);
    for (const step of executedSteps.reverse()) {
      await step.compensate(orderId);
    }
  }
}
```

# Circuit Breaker Pattern

## 障害の連鎖防止

### **基本実装**
```typescript
enum CircuitState {
  CLOSED,   // 正常
  OPEN,     // 遮断
  HALF_OPEN // 半開
}

class CircuitBreaker<T> {
  private state = CircuitState.CLOSED;
  private failureCount = 0;
  private lastFailureTime?: Date;

  async execute(operation: () => Promise<T>): Promise<T> {
    if (this.state === CircuitState.OPEN) {
      if (this.shouldAttemptReset()) {
        this.state = CircuitState.HALF_OPEN;
      } else {
        throw new CircuitBreakerOpenError();
      }
    }

    try {
      const result = await operation();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  private onSuccess(): void {
    this.failureCount = 0;
    this.state = CircuitState.CLOSED;
  }

  private onFailure(): void {
    this.failureCount++;
    this.lastFailureTime = new Date();

    if (this.failureCount >= this.failureThreshold) {
      this.state = CircuitState.OPEN;
    }
  }
}
```

# Clean Architecture

## 依存性の方向制御

### **依存性ルール**
```
🎯 依存の方向: 外側 → 内側 (一方向のみ)

┌────────────────────────────────────────────┐
│ Frameworks & Drivers (Web, DB, External)  │

│ Interface Adapters (Controllers, Gateways)│
```

# 分散システムの理論的基盤

## CAP定理

### **Consistency・Availability・Partition Tolerance**
```
┌─────────────────┐    ┌─────────────────┐
│       CA        │    │       CP        │
│   RDBMS系       │    │   MongoDB       │
│ (分散ではない)   │    │   Redis Cluster │
└─────────────────┘    └─────────────────┘
           ┌─────────────────┐
           │       AP        │
           │   DynamoDB      │
           │   Cassandra     │
           └─────────────────┘
```

### **実用的選択**
- **CP**: 金融システム、在庫管理
- **AP**: ソーシャルメディア、ログ収集
- **CA**: 単一データセンター内システム

## BASE vs ACID

### **ACID (従来)**
- **Atomicity**: 原子性
- **Consistency**: 一貫性
- **Isolation**: 分離性
- **Durability**: 永続性

### **BASE (分散システム)**
- **Basically Available**: 基本的可用性
- **Soft state**: ソフトステート
- **Eventual consistency**: 結果的整合性

# パフォーマンス設計原則

## レイテンシ vs スループット

### **レイテンシ最適化**
```typescript
// キャッシュ戦略
class ProductService {
  constructor(
    private cache: CacheService,
    private repository: ProductRepository
  ) {}

  async getProduct(id: ProductId): Promise<Product> {
    // L1: メモリキャッシュ（1ms）
    let product = this.memoryCache.get(id);
    if (product) return product;

    // L2: Redisキャッシュ（10ms）
    product = await this.cache.get(id);
    if (product) {
      this.memoryCache.set(id, product);
      return product;
    }

    // L3: データベース（100ms）
    product = await this.repository.findById(id);
    await this.cache.set(id, product);
    this.memoryCache.set(id, product);
    
    return product;
  }
}
```

### **スループット最適化**
```typescript
// バッチ処理・並列化
class OrderProcessingService {
  async processBatch(orders: Order[]): Promise<void> {
    const chunks = this.chunkArray(orders, 100); // バッチサイズ

    await Promise.all(
      chunks.map(chunk => this.processChunk(chunk))
    );
  }

  private async processChunk(orders: Order[]): Promise<void> {
    // データベース接続プールを活用
    await this.repository.batchUpdate(orders);
  }
}
```

# 分散システムのコンセンサスアルゴリズム

## Raftアルゴリズム

### **リーダー選出プロセス**
```typescript
enum NodeState { FOLLOWER, CANDIDATE, LEADER }

class RaftNode {
  private state = NodeState.FOLLOWER;
  private currentTerm = 0;
  private votedFor?: NodeId;

  async startElection(): Promise<void> {
    this.state = NodeState.CANDIDATE;
    this.currentTerm++;
    this.votedFor = this.nodeId;

    const votes = await this.requestVotes();
    
    if (votes > this.clusterSize / 2) {
      this.becomeLeader();
    } else {
      this.state = NodeState.FOLLOWER;
    }
  }

  async appendEntries(entries: LogEntry[]): Promise<boolean> {
    if (this.state !== NodeState.LEADER) {
      throw new NotLeaderError();
    }

    // 過半数のフォロワーに複製
    const replicationResults = await Promise.allSettled(
      this.followers.map(follower => follower.replicate(entries))
    );

    const successCount = replicationResults
      .filter(result => result.status === 'fulfilled').length;

    return successCount >= this.clusterSize / 2;
  }
}
```
