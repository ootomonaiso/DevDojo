# なぜプログラムの書き方が大切なの？

## 悪いプログラムの例 😵
- **スパゲッティコード** - からまった麺のように複雑
- **理解できない** - 1週間後に自分のコードがわからない
- **バグだらけ** - 1つ直すと別の場所が壊れる
- **時間がかかる** - 機能追加に何日もかかる

## 良いプログラムの例 �
- **読みやすい** - 他の人でもすぐ理解できる
- **安全** - バグが起きにくい
- **変更しやすい** - 新機能をサクッと追加できる

# 基本ルール1：1つのことだけやる

## 悪い例
```javascript
// 計算も表示もメール送信も全部やってる
function doEverything(price, tax) {
  const total = price + (price * tax);
  console.log(`合計: ${total}円`);
  sendEmailToCustomer(total);
  return total;
}
```

## 良い例
```javascript
// 計算だけ
function calculateTotal(price, tax) {
  return price + (price * tax);
}

// 表示だけ
function displayTotal(total) {
  console.log(`合計: ${total}円`);
}

// メール送信だけ
function sendEmail(total) {
  sendEmailToCustomer(total);
}
```

---

# 基本ルール2：わかりやすい名前をつける

## 悪い例
```javascript
function calc(a, b) {
  return a * b * 1.1;
}

let x = calc(1000, 2);
```

## 良い例
```javascript
function calculatePriceWithTax(price, quantity) {
  const TAX_RATE = 1.1;
  return price * quantity * TAX_RATE;
}

let totalPrice = calculatePriceWithTax(1000, 2);
```

**ポイント**：
- 何をする関数か一目でわかる
- 変数の意味がすぐ理解できる

---

# 基本ルール3：短く書く

## 悪い例 - 長すぎる関数
```javascript
function processOrder() {
  // 50行のコード...
  // 顧客情報チェック
  // 在庫確認
  // 価格計算
  // メール送信
  // データベース保存
  // ログ出力
}
```

## 良い例 - 小さな関数に分ける
```javascript
function processOrder() {
  validateCustomer();
  checkStock();
  const price = calculatePrice();
  sendNotification();
  saveToDatabase();
  writeLog();
}
```

---

# 基本ルール4：同じコードを書かない

## 悪い例 - コピペだらけ
```javascript
function calculateApplePrice() {
  const basePrice = 100;
  const tax = basePrice * 0.1;
  return basePrice + tax;
}

function calculateOrangePrice() {
  const basePrice = 150;
  const tax = basePrice * 0.1;  // 同じ計算をコピペ
  return basePrice + tax;       // 同じ計算をコピペ
}
```

## 良い例 - 共通部分をまとめる
```javascript
function calculatePriceWithTax(basePrice) {
  const tax = basePrice * 0.1;
  return basePrice + tax;
}

function calculateApplePrice() {
  return calculatePriceWithTax(100);
}

function calculateOrangePrice() {
  return calculatePriceWithTax(150);
}
```

# プログラムの組み立て方

## レゴブロックのように考える

### 悪い組み立て方
- **巨大な1つのブロック** → 使い回しできない
- **ぐちゃぐちゃに接続** → 構造がわからない

### 良い組み立て方
- **小さなブロックを組み合わせ** → 再利用できる
- **きれいに整理** → 構造が一目でわかる

## 具体例：ショッピングサイト
```
トップページ
├── 商品一覧表示
├── カート機能
├── 支払い処理
└── 確認メール送信
```

# よくある間違いパターン

## 1. 魔法の数字 🎩
```javascript
// 悪い例 - 0.1って何？
const total = price * 0.1;

// 良い例 - 意味がわかる
const TAX_RATE = 0.1;
const total = price * TAX_RATE;
```

## 2. 意味不明な略語
```javascript
// 悪い例
let usr = getUserInfo();
let calc = calcPrice(usr.prc);

// 良い例
let user = getUserInfo();
let totalPrice = calculatePrice(user.price);
```

# テストの大切さ 🧪

## テストって何？
プログラムが正しく動くかチェックすること

## 簡単なテストの例
```javascript
// 計算する関数
function add(a, b) {
  return a + b;
}

// テスト - 期待した結果になるかチェック
function testAdd() {
  const result = add(2, 3);
  if (result === 5) {
    console.log('✅ テスト成功！');
  } else {
    console.log('❌ テスト失敗！');
  }
}

testAdd(); // ✅ テスト成功！
```

**なぜテストが大切？**
- バグを早く見つけられる
- 安心してコードを変更できる

## 📚 この講座で学べること

### ✅ 基本スキル
- **読みやすいコード**: 他の人（未来の自分含む）が理解できるコード

- **変更しやすいコード**: 新機能追加や修正が楽にできる

- **関数の分け方**: 大きな問題を小さく分ける方法
- **名前の付け方**: わかりやすい変数名・関数名のコツ
- **コードの整理**: ファイルや機能の整理方法
